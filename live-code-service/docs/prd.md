# PRD — 라이브 참여 코드 발급 서비스

| 항목 | 내용 |
|------|------|
| 문서 버전 | v0.1 |
| 작성일 | 2026-06-04 |
| 상태 | 초안 |

---

## 1. 배경 및 목적

실시간 라이브 강의·이벤트에 참여한 기존 회원에게 한정 코드를 발급함으로써, 라이브 참여 유인을 높이고 코드를 통한 혜택(할인, 자료 다운로드 등)을 제공한다. 수기 관리 대신 자동화된 발급 시스템으로 운영 부담을 줄이는 것이 목표다.

---

## 2. 목표 (Goals)

| 우선순위 | 목표 |
|----------|------|
| P0 | 라이브 진행 중에만 코드 발급 가능하도록 제어 |
| P0 | 기존 가입자만 코드를 발급받을 수 있음 |
| P0 | 1인 1코드 보장 (중복 발급 불가) |
| P1 | 관리자가 라이브 세션을 직접 켜고 끌 수 있음 |
| P1 | 발급 내역을 조회하고 코드를 일괄 무효화할 수 있음 |
| P2 | 코드 유효기간 및 사용 여부 추적 |
| P2 | 선착순 발급 수량 제한 |

---

## 3. 대상 사용자

### 3-1. 일반 사용자 (라이브 참여자)
- 기존에 서비스에 가입한 회원
- 실시간 라이브를 시청하면서 코드를 발급받고자 하는 사람
- 디지털 기기에 익숙하나 복잡한 절차를 원하지 않음

### 3-2. 관리자 (운영자)
- 라이브를 직접 진행하거나 운영을 담당하는 내부 인원
- 라이브 시작/종료 시 세션을 제어하고, 발급 현황을 모니터링함

---

## 4. 핵심 기능 정의

### 4-1. 코드 발급 (사용자)

**발급 조건 (AND 조건, 모두 충족 시에만 발급)**

| 조건 | 설명 | 위반 시 |
|------|------|---------|
| 기존 가입자 | DB의 `members` 컬렉션에 이메일이 존재 | "등록된 회원 정보가 없습니다" 안내 |
| 라이브 중 | `live_sessions/current.isActive === true` | "현재 라이브가 진행 중이지 않습니다" 안내 |
| 미발급 | `issued_codes`에 해당 이메일 문서 없음 | 기발급 코드 재노출 |
| 수량 제한 | 발급 총 건수 < 설정된 maxCount (옵션) | "코드 수량이 소진되었습니다" 안내 |

**발급 흐름**
```
이메일 입력 → 라이브 활성 확인 → 회원 확인 → 중복 확인 → 코드 생성 → 저장 → 화면 노출
```

**코드 형식**
- 패턴: `LIVE-XXXXXXXX` (X = 대문자 알파뉴메릭, 혼동 문자 제외)
- 예시: `LIVE-4KQMR7BN`

### 4-2. 세션 제어 (관리자)

- 라이브 시작 시: `live_sessions/current.isActive = true` 로 전환
- 라이브 종료 시: `live_sessions/current.isActive = false` 로 전환
- 최대 발급 수량(maxCount) 설정 가능

### 4-3. 발급 내역 조회 (관리자)

- 발급된 코드 목록 (이메일, 코드, 발급 시각, 사용 여부)
- CSV 다운로드
- 코드 일괄 무효화

---

## 5. 비기능 요구사항

| 항목 | 요건 |
|------|------|
| 동시성 | Firestore 트랜잭션으로 중복 발급 race condition 방지 |
| 응답 속도 | 발급 API 응답 3초 이내 |
| 보안 | 관리자 페이지는 별도 패스워드 보호 |
| 가용성 | Firebase 무료 티어 기준 (읽기 50,000건/일, 쓰기 20,000건/일) |
| 확장성 | 수천 명 규모 라이브에서도 무료 티어 내 운용 가능 |

---

## 6. 제외 범위 (Out of Scope, v1)

- 코드 사용 처리 (코드를 입력받아 검증하는 기능 — 별도 서비스에서 담당)
- 이메일 발송 (코드를 이메일로 전송)
- 소셜 로그인 / OTP 인증
- 다국어 지원

---

## 7. 성공 지표

| 지표 | 목표 |
|------|------|
| 발급 오류율 | < 1% |
| 중복 발급 건수 | 0건 |
| 평균 발급 소요 시간 | < 3초 |
| 관리자 세션 제어 오작동 | 0건 |

## 9. 데이터 모델

### `members` 컬렉션
```
{
  email: string,       // 가입 이메일 (소문자 정규화)
  name?: string,       // 이름 (선택)
  joinedAt: Timestamp
}
```

### `live_sessions/current` 문서
```
{
  isActive: boolean,   // 라이브 활성 여부
  maxCount?: number,   // 최대 발급 수량 (미설정 시 무제한)
  startedAt?: Timestamp,
  endedAt?: Timestamp
}
```

### `issued_codes` 컬렉션
```
{
  // 문서 ID = 이메일 (소문자) — 중복 방지 핵심
  email: string,
  code: string,        // LIVE-XXXXXXXX
  issuedAt: Timestamp,
  isUsed: boolean,
  usedAt?: Timestamp
}
```
