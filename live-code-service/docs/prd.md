# PRD — 라이브 참여 코드 발급 서비스

| 항목 | 내용 |
|------|------|
| 문서 버전 | v0.4 |
| 작성일 | 2026-06-04 |
| 상태 | 초안 |
| 변경 이력 | v0.2: 4-50대 학부모 페르소나 반영 / v0.3: 5개 반 멀티 클래스 구조 반영 / v0.4: 시뮬레이션 15개 엣지케이스 반영 (EC-N01~N15) |

---

## 1. 배경 및 목적

실시간 라이브 강의·이벤트에 참여한 기존 회원에게 한정 코드를 발급함으로써, 라이브 참여 유인을 높이고 코드를 통한 혜택(할인, 자료 다운로드 등)을 제공한다. 수기 관리 대신 자동화된 발급 시스템으로 운영 부담을 줄이는 것이 목표다.

**v0.3 추가 배경:** 동일 강의가 5개 반으로 나뉘어 각기 다른 시간에 진행되며, 각 반에 할당된 코드가 서로 다르다. 회원은 자신이 속한 반의 코드만 발급받아야 한다.

## 2. 목표 (Goals)

| 우선순위 | 목표 |
|----------|------|
| P0 | 기존 가입자만 코드를 발급받을 수 있음 |
| P0 | 회원이 이메일을 입력하면 자신이 속한 반 정보가 표시됨 |
| P0 | 자신의 반 라이브 진행 중에만 코드 발급 가능 (반별 독립 세션) |
| P0 | 1인 1코드 보장 (중복 발급 불가) |
| P0 | 반별로 서로 다른 코드 발급 |
| P1 | 관리자가 5개 반 각각의 세션을 독립적으로 제어 |
| P1 | 발급 내역을 반별로 조회하고 코드를 무효화할 수 있음 |
| P2 | 코드 유효기간 및 사용 여부 추적 |
| P2 | 반별 선착순 발급 수량 제한 |

## 3. 대상 사용자

### 3-1. 일반 사용자 (라이브 참여 학부모)
- 기존에 강의에 등록한 회원 (40-50대, 인터넷·모바일 조작 익숙하지 않음)
- 5개 반 중 1개 반에 배정되어 있음
- 모바일(스마트폰)로 접속하는 경우가 대부분

### 3-2. 관리자 (운영자)
- 라이브를 직접 진행하거나 운영을 담당하는 내부 인원
- 5개 반 각각의 라이브 시간이 다르므로 반별로 세션을 독립 제어해야 함
- 발급 현황을 반별로 모니터링

## 4. 핵심 기능 정의

### 4-1. 반 확인 (1단계)

사용자가 이메일을 입력하면 해당 이메일이 어떤 반에 속하는지 조회해 화면에 표시한다.

| 조건 | 설명 | 결과 |
|------|------|------|
| 이메일이 `members` DB에 존재 | classId로 `classes` 컬렉션 조회 | 반 이름·시간 화면 표시 |
| 이메일이 DB에 없음 | — | 미가입 안내 |

표시 정보: **반 이름** (예: 3반), **강의 예정 시각** (예: 6월 10일 오후 2시)

### 4-2. 코드 발급 (2단계)

반 정보를 확인한 사용자가 "맞아요, 코드 받기" 버튼을 누르면 발급 조건을 검증하고 코드를 발급한다.

**발급 조건 (AND 조건, 순서대로 검증)**

| 순서 | 조건 | 설명 | 위반 시 |
|------|------|------|---------|
| 1 | 기발급 확인 | `issued_codes`에 이메일 문서가 이미 있으면 | 기발급 코드 재노출 (세션 상태 무관) |
| 2 | 반 세션 활성 | 해당 반의 `isActive === true` | 시작 전 / 종료 후 안내 |
| 3 | 수량 제한 | 해당 반 발급 건수 < maxCodes (설정 시) | 수량 소진 안내 |
| 4 | 코드 생성·저장 | `issued_codes`에 트랜잭션으로 저장 | — |

**코드 형식**
- 패턴: `LIVE-XXXXXXXX` (X = 대문자 알파뉴메릭, 혼동 문자 O·0·I·1·L 제외)
- 반 정보는 코드 문자열에 포함하지 않고 DB(`classId`)로 관리
- 예시: `LIVE-4KQMR7BN`

### 4-3. 반별 세션 제어 (관리자)

- 5개 반 각각을 독립적으로 ON/OFF
- 반마다 강의 예정 시각(`scheduledAt`), 최대 발급 수량(`maxCodes`), 운영자 연락처를 설정
- 한 반이 ON 상태여도 다른 반은 OFF 상태일 수 있음

### 4-4. 발급 내역 조회 (관리자)

- 전체 또는 반별 필터로 발급 목록 조회
- 이메일, 코드, 반, 발급 시각, 사용 여부 표시
- CSV 다운로드, 개별·일괄 무효화

## 5. 비기능 요구사항

| 항목 | 요건 |
|------|------|
| 동시성 | Firestore 트랜잭션으로 중복 발급 race condition 방지 |
| 응답 속도 | 반 조회 API < 2초, 코드 발급 API < 3초 |
| 보안 | 관리자 페이지 패스워드 보호, Firebase 키 서버 환경변수 관리 |
| 가용성 | Firebase 무료 티어 (읽기 50,000건/일, 쓰기 20,000건/일) — 5개 반 합산 기준 |
| 확장성 | 반당 수십~수백 명 규모 동시 요청 처리 |

## 6. 제외 범위 (Out of Scope, v1)

- 코드 사용 처리 (코드를 입력받아 검증하는 기능 — 별도 서비스에서 담당)
- 이메일 발송 (코드를 이메일로 전송)
- 소셜 로그인 / OTP 인증
- 다국어 지원
- 반 자동 배정 (회원 등록 시 반 배정은 외부 시스템에서 처리)

| 지표 | 목표 |
|------|------|
| 발급 오류율 | < 1% |

## 9. 데이터 모델

### `classes` 컬렉션 (신규 — live_sessions 대체)
```
{
  // 문서 ID = "class-1" ~ "class-5"
  name: string,              // 표시 이름 (예: "1반", "오전반")
  scheduledAt: Timestamp,    // 강의 예정 시작 시각
  isActive: boolean,         // 현재 코드 발급 가능 여부
  maxCodes?: number,         // 최대 발급 수량 (미설정 시 무제한)
  instructorContact?: string,// 운영자 연락처 (에러 화면 노출용)
  startedAt?: Timestamp,     // 실제 세션 시작 시각
  endedAt?: Timestamp        // 실제 세션 종료 시각
}
```

### `members` 컬렉션 (classId 필드 추가)
```
{
  // 문서 ID = 이메일 (소문자) — 동일 이메일 이중 등록 방지 (EC-N14)
  email: string,      // 소문자 정규화 이메일
  classId: string,    // 소속 반 ID (예: "class-3")
  name?: string,
  joinedAt: Timestamp
}
```

### `issued_codes` 컬렉션 (classId 필드 추가)
```
{
  // 문서 ID = 이메일 (소문자) — 중복 방지 핵심
  email: string,
  classId: string,    // 발급 시점의 소속 반
  code: string,       // LIVE-XXXXXXXX
  issuedAt: Timestamp,
  isUsed: boolean,
  usedAt?: Timestamp,
  isRevoked?: boolean
}
```

### `issued_codes_meta/{classId}` 문서 (신규 — 반별 카운터)
```
{
  total: number  // 해당 반 발급 총 건수 — maxCodes atomic 체크용
}
```

## 10. API 설계

### `POST /api/check-member`
이메일로 회원 여부와 소속 반 정보를 조회한다.

**Request:** `{ email: string }`

**Response 성공:** `{ classId, className, scheduledAt?, isActive }`

**Response 실패:**

| HTTP | 사유 | `error` 값 |
|------|------|-----------|
| 400 | 이메일 형식 오류 | `"INVALID_EMAIL"` |
| 404 | 미가입 이메일 | `"MEMBER_NOT_FOUND"` |
| 404 | classId 미설정 또는 classes 문서 없음 | `"CLASS_NOT_ASSIGNED"` (EC-N01, EC-N02) |
| 429 | rate limit 초과 | `"TOO_MANY_REQUESTS"` (EC-N09) |
| 500 | 서버/DB 오류 | `"SERVER_ERROR"` |

---

### `POST /api/issue-code`
소속 반의 코드를 발급한다. 내부적으로 회원 재검증 후 발급.

**Request:** `{ email: string }`

**Response 신규:** `{ code, classId, className }` (201)

**Response 기발급:** `{ code, classId, className, alreadyIssued: true }` (200)

**Response 실패:** `{ error: string }` (400/403/500)
