# 요구사항 정의서 — 라이브 참여 코드 발급 서비스

| 항목 | 내용 |
|------|------|
| 문서 버전 | v0.1 |
| 작성일 | 2026-06-04 |
| 상태 | 초안 |

---

## 1. 기능 요구사항

### FR-01. 코드 발급

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-01-01 | 사용자는 이메일 주소를 입력하여 코드를 발급받을 수 있다 | 필수 |
| FR-01-02 | 이메일이 `members` DB에 존재하지 않으면 코드를 발급하지 않는다 | 필수 |
| FR-01-03 | 라이브 세션이 활성화되어 있지 않으면 코드를 발급하지 않는다 | 필수 |
| FR-01-04 | 동일 이메일로 이미 코드가 발급된 경우 신규 발급하지 않으며, 기발급 코드를 안내한다 | 필수 |
| FR-01-05 | 동시 요청이 들어와도 1인 1코드를 보장한다 (Firestore 트랜잭션) | 필수 |
| FR-01-06 | 발급된 코드는 `LIVE-XXXXXXXX` 형식이며 대소문자 혼동 문자(O, 0, I, 1, L)를 제외한다 | 필수 |
| FR-01-07 | 최대 발급 수량이 설정된 경우, 수량 초과 시 발급을 거부한다 | 권장 |
| FR-01-08 | 코드 발급 시 발급 시각을 기록한다 | 필수 |

### FR-02. 세션 관리 (관리자)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-02-01 | 관리자는 라이브 세션을 시작/종료할 수 있다 | 필수 |
| FR-02-02 | 세션 시작 시 시작 시각을 기록한다 | 필수 |
| FR-02-03 | 세션 종료 시 종료 시각을 기록한다 | 필수 |
| FR-02-04 | 관리자는 최대 발급 수량을 설정할 수 있다 | 권장 |
| FR-02-05 | 관리자 페이지는 비인가 접근으로부터 보호된다 | 필수 |

### FR-03. 발급 내역 관리 (관리자)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-03-01 | 관리자는 발급된 코드 전체 목록을 조회할 수 있다 | 필수 |
| FR-03-02 | 목록에는 이메일, 코드, 발급 시각, 사용 여부가 표시된다 | 필수 |
| FR-03-03 | 관리자는 특정 코드를 개별 무효화할 수 있다 | 권장 |
| FR-03-04 | 관리자는 전체 코드를 일괄 무효화할 수 있다 | 권장 |
| FR-03-05 | 관리자는 발급 내역을 CSV로 다운로드할 수 있다 | 선택 |

### FR-04. 코드 유효성

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-04-01 | 코드에는 유효기간이 존재할 수 있다 (미설정 시 무기한) | 선택 |
| FR-04-02 | 코드 사용 여부(`isUsed`)를 추적한다 | 권장 |
| FR-04-03 | 무효화된 코드는 사용 불가 처리된다 | 권장 |

## 2. 비기능 요구사항

### NFR-01. 성능

| ID | 요구사항 |
|----|----------|
| NFR-01-01 | 코드 발급 API 응답 시간은 정상 상황에서 3초 이내여야 한다 |
| NFR-01-02 | 라이브 이벤트 시 동시 요청 100건 이상을 처리할 수 있어야 한다 |

### NFR-02. 보안

| ID | 요구사항 |
|----|----------|
| NFR-02-01 | 관리자 페이지는 인증 없이 접근할 수 없다 |
| NFR-02-02 | Firebase 서비스 계정 키는 서버 환경변수로만 관리하며 클라이언트에 노출하지 않는다 |
| NFR-02-03 | 이메일 입력값은 서버에서 소문자 정규화하여 처리한다 |
| NFR-02-04 | API는 적절한 HTTP 상태코드와 최소한의 에러 메시지만 반환한다 |

### NFR-03. 가용성

| ID | 요구사항 |
|----|----------|
| NFR-03-01 | Firebase Firestore 무료 티어(읽기 50,000건/일, 쓰기 20,000건/일) 범위 내에서 운용 가능해야 한다 |
| NFR-03-02 | 단일 라이브 이벤트 참여자 수천 명 규모를 감당해야 한다 |

### NFR-04. 유지보수성

| ID | 요구사항 |
|----|----------|
| NFR-04-01 | 이 서비스는 다른 서비스와 독립적으로 배포 가능해야 한다 |
| NFR-04-02 | 환경변수만 교체하면 Firebase 프로젝트를 교체할 수 있어야 한다 |

## 3. 제약 사항

| ID | 제약 |
|----|------|
| CON-01 | Firebase 무료 티어(Spark Plan)를 사용한다 |
| CON-02 | 별도 서버 인프라 없이 Vercel 서버리스 환경에서 운용한다 |
| CON-03 | 코드 사용(redemption) 처리는 이 서비스의 범위가 아니다 |
| CON-04 | 이메일 발송 기능은 v1에서 제외한다 |

## 4. 에러 케이스 정의

| 상황 | HTTP 상태코드 | 사용자 메시지 |
|------|--------------|--------------|
| 이메일 미입력 또는 형식 오류 | 400 | "이메일을 올바르게 입력해주세요." |
| 라이브 세션 비활성 | 403 | "현재 라이브가 진행 중이지 않습니다." |
| 미가입 이메일 | 403 | "등록된 회원 정보가 없습니다." |
| 수량 소진 | 403 | "코드 수량이 모두 소진되었습니다." |
| 이미 발급됨 | 200 | "이미 발급된 코드입니다." + 코드 노출 |
| 서버 오류 | 500 | "코드 발급 중 오류가 발생했습니다. 다시 시도해주세요." |

## 5. 용어 정의

| 용어 | 정의 |
|------|------|
| 라이브 세션 | 관리자가 활성화한 코드 발급 가능 구간 |
| 코드 | `LIVE-XXXXXXXX` 형식의 고유한 문자열 |
| 기존 가입자 | `members` 컬렉션에 이메일이 등록된 사용자 |
| 관리자 | 라이브 세션을 제어하고 발급 내역을 조회할 수 있는 내부 운영자 |
| 무효화 | 코드를 사용 불가 상태로 전환하는 행위 |
