## 0. 핵심 페르소나 & 설계 원칙

**대상 사용자:** 인터넷·모바일 조작에 익숙하지 않은 40-50대 학부모

| 특성 | 영향 |
|------|------|
| 이메일 주소를 정확히 기억하지 못할 수 있음 | 에러 시 대안 경로(운영자 연락처) 필수 |
| 모바일(스마트폰) 위주로 접속 | 터치 타겟 최소 44px, 코드 복사 버튼 필수 |
| 에러 메시지를 보면 "내가 뭔가 고장냈나" 불안해함 | 부정적 표현 최소화, 다음 행동 지시 항상 포함 |
| 카카오톡 인앱 브라우저로 접속하는 경우 많음 | 클립보드 API 폴백 처리 필요 |
| 코드 받은 후 화면을 바로 닫아버릴 수 있음 | 세션 종료 후에도 기발급 코드 재확인 가능해야 함 |
| 화면을 오래 보면 글씨가 잘 안 보임 | 최소 16px 폰트, 코드는 28px 이상, WCAG AA 대비 충족 |

**UX 언어 원칙**
- 전문용어 금지 ("세션", "서버 오류" → "강의가 아직 시작되지 않았어요", "일시적인 문제가 생겼어요")
- 모든 오류 화면에 **다음 행동 지시** 포함 (무엇을 해야 하는지)
- 모든 오류 화면에 **운영자 연락처** 포함 (마지막 구제 수단)
- "이미 발급된 코드" 등 재확인 상황은 긍정적 표현으로 처리

## 1. 기능 요구사항

### FR-01. 코드 발급

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| FR-01-01 | 사용자는 이메일 주소를 입력하여 코드를 발급받을 수 있다 | 필수 |
| FR-01-02 | 이메일이 `members` DB에 존재하지 않으면 코드를 발급하지 않는다 | 필수 |
| FR-01-03 | 라이브 세션이 활성화되어 있지 않으면 코드를 발급하지 않는다 | 필수 |
| FR-01-04 | 동일 이메일로 이미 코드가 발급된 경우 신규 발급하지 않으며, 기발급 코드를 노출한다 | 필수 |
| FR-01-05 | 동시 요청이 들어와도 1인 1코드를 보장한다 (Firestore 트랜잭션) | 필수 |
| FR-01-06 | 발급된 코드는 `LIVE-XXXXXXXX` 형식이며 혼동 문자(O, 0, I, 1, L)를 제외한다 | 필수 |
| FR-01-07 | 최대 발급 수량이 설정된 경우, 수량 초과 시 발급을 거부한다 | 권장 |
| FR-01-08 | 코드 발급 시 발급 시각을 기록한다 | 필수 |
| FR-01-09 | **[신규]** API에서 이메일 형식 정규표현식 검증을 수행한다 (브라우저 검증에만 의존하지 않음) | 필수 |
| FR-01-10 | **[신규]** 기발급 코드 조회는 라이브 세션 활성 여부와 무관하게 동작한다 (세션 종료 후에도 코드 재확인 가능) | 필수 |
| FR-01-11 | **[신규]** 클라이언트에서 이메일 제출 전 공백(앞뒤·중간)을 제거한다 | 필수 |
| FR-01-12 | **[신규]** fetch 요청에 타임아웃(10초)을 설정하며, 초과 시 네트워크 오류 안내를 표시한다 | 권장 |

## 2. 비기능 요구사항

### NFR-01. 성능

| ID | 요구사항 |
|----|----------|
| NFR-01-01 | 코드 발급 API 응답 시간은 정상 상황에서 3초 이내여야 한다 |
| NFR-01-02 | 라이브 이벤트 시 동시 요청 100건 이상을 처리할 수 있어야 한다 |
| NFR-01-03 | **[신규]** 클라이언트 fetch 타임아웃은 10초로 설정한다 |

### NFR-02. 보안

| ID | 요구사항 |
|----|----------|
| NFR-02-01 | 관리자 페이지는 인증 없이 접근할 수 없다 |
| NFR-02-02 | Firebase 서비스 계정 키는 서버 환경변수로만 관리하며 클라이언트에 노출하지 않는다 |
| NFR-02-03 | 이메일 입력값은 서버에서 소문자 정규화 및 공백 제거 후 처리한다 |
| NFR-02-04 | API는 적절한 HTTP 상태코드와 최소한의 에러 메시지만 반환한다 |
| NFR-02-05 | **[신규]** API에서 이메일 형식을 정규표현식으로 검증한다 |

### NFR-03. 가용성

| ID | 요구사항 |
|----|----------|
| NFR-03-01 | Firebase Firestore 무료 티어(읽기 50,000건/일, 쓰기 20,000건/일) 범위 내에서 운용 가능해야 한다 |
| NFR-03-02 | 단일 라이브 이벤트 참여자 수천 명 규모를 감당해야 한다 |

### NFR-04. 접근성 및 호환성

| ID | 요구사항 |
|----|----------|
| NFR-04-01 | **[신규]** 모든 텍스트는 WCAG AA 기준(대비 4.5:1 이상)을 충족한다 |
| NFR-04-02 | **[신규]** 코드 표시 폰트는 28px 이상으로 스크린샷 시 가독성을 보장한다 |
| NFR-04-03 | **[신규]** 터치 타겟(버튼, 링크) 최소 크기는 44×44px 이상이어야 한다 |
| NFR-04-04 | **[신규]** 카카오톡 인앱 브라우저, 구형 안드로이드 브라우저에서 핵심 기능이 동작해야 한다 |
| NFR-04-05 | **[신규]** 320px 이상의 화면 너비에서 코드가 한 줄로 표시되어야 한다 (줄바꿈 금지) |

### NFR-05. 유지보수성

| ID | 요구사항 |
|----|----------|
| NFR-05-01 | 이 서비스는 다른 서비스와 독립적으로 배포 가능해야 한다 |
| NFR-05-02 | 환경변수만 교체하면 Firebase 프로젝트를 교체할 수 있어야 한다 |

## 4. 에러 케이스 정의

| 상황 | HTTP | 사용자 친화 메시지 | 후속 지시 |
|------|------|--------------------|----------|
| 이메일 형식 오류 (클라이언트) | — | "이메일 주소를 정확히 입력해 주세요." | "예시: 홍길동@naver.com (@과 . 이 포함되어야 합니다)" |
| 이메일 형식 오류 (API) | 400 | "이메일 주소를 다시 확인해 주세요." | 위 동일 |
| 라이브 아직 시작 전 | 403 | "아직 강의가 시작되지 않았습니다." | "강사 선생님의 안내에 따라 다시 시도해 주세요." |
| 라이브 종료 후 | 403 | "코드 발급이 종료되었습니다." | "코드를 받지 못하셨다면 강사 선생님께 직접 문의해 주세요." + 연락처 |
| 미가입 이메일 (1-2회) | 403 | "입력하신 이메일로 가입된 정보를 찾을 수 없습니다." | "가입할 때 사용한 이메일을 다시 확인해 주세요." |
| 미가입 이메일 (3회+) | 403 | 위 동일 | 위 동일 + 운영자 연락처 강조 |
| 수량 소진 | 403 | "준비된 코드가 모두 소진되었습니다." | "강사 선생님께 직접 말씀해 주시면 도움을 드릴 수 있습니다." + 연락처 |
| 이미 발급됨 | 200 | "이전에 발급받으신 코드입니다. 그대로 사용하시면 됩니다." | 코드 재노출 + 복사 버튼 |
| 네트워크 오류 | — | "인터넷 연결이 끊어진 것 같습니다." | "와이파이나 데이터를 확인하신 후 다시 눌러주세요." + [다시 시도] 버튼 |
| 타임아웃 | — | "응답이 너무 오래 걸립니다." | "다시 눌러주세요. 계속되면 강사 선생님께 알려주세요." + [다시 시도] |
| 서버 오류 | 500 | "일시적인 문제가 생겼습니다." | "잠시 후 다시 시도해 주세요." + [다시 시도] + 연락처 |

## 5. 엣지케이스 목록 (시뮬레이션 결과)

> 대상: 40-50대 학부모 페르소나 시뮬레이션 (2026-06-04)

| EC# | 시나리오 | 심각도 | 구현 필요 |
|-----|----------|--------|----------|
| EC-01 | 가입 이메일을 잘못 기억해 여러 번 실패 | 높음 | 에러 메시지에 힌트 + 운영자 연락처 |
| EC-02 | 이메일 중간에 공백 삽입 (모바일 자동완성) | 높음 | 클라이언트에서 공백 제거 후 재표시 |
| EC-03 | 도메인을 몰라 naver/daum/gmail 순차 시도 | 중간 | 3회 실패 시 운영자 연락처 강조 |
| EC-04 | 브라우저 자동완성이 엉뚱한 이메일 입력 | 높음 | 발급된 이메일 확인 문구 성공 화면에 표시 |
| EC-05 | 모바일 데이터 불안정으로 fetch 중 끊김 | 높음 | AbortController 타임아웃 10초 |
| EC-06 | 코드 확인 후 실수로 화면 닫아 코드 분실 | 높음 | 코드 복사 버튼 + 재확인 안내 문구 |
| EC-07 | 야외에서 스크린샷 찍었는데 코드가 안 보임 | 중간 | WCAG AA 대비 충족, 코드 28px 이상 |
| EC-08 | 라이브 시작 전에 미리 접속해 "오류"로 오해 | 높음 | "아직 시작 전" 메시지 + scheduledAt 안내 |
| EC-09 | 세션 종료 후 코드 분실 → 재확인 불가 | 긴급 | 기발급 조회를 세션 체크보다 먼저 수행 |
| EC-10 | 강사가 실수로 세션 껐다 바로 재개 | 중간 | 오류 화면에 [다시 시도] 버튼 |
| EC-11 | 부부가 같은 계정으로 각자 코드 받으려 함 | 중간 | "같은 이메일은 하나의 코드만 발급" 안내 |
| EC-12 | 자녀가 학부모 대신 이메일 입력해 대리 수령 | 낮음 | isUsed 추적 (v2 코드 검증 시 해결) |
| EC-13 | 수량 소진 체크 로직이 코드에 미구현 | 긴급 | 카운터 문서 기반 atomic 체크 구현 |
| EC-14 | Firebase 환경변수 누락 시 기본 500 화면 노출 | 높음 | error.tsx 글로벌 에러 페이지 추가 |
| EC-15 | Firestore 느릴 때 버튼 여러 번 탭 | 높음 | 스피너 + disabled 시각 피드백 강화 |
| EC-16 | API 이메일 형식 검증 없음 (구형 브라우저) | 높음 | API에 정규표현식 검증 추가 |
| EC-17 | 카카오 인앱 브라우저에서 클립보드 접근 실패 | 중간 | readonly input 폴백 처리 |
| EC-18 | 성공 후 다른 이메일로 재발급받을 방법 없음 | 낮음 | "다른 이메일로 받기" 링크 |
| EC-19 | 320px 구형폰에서 코드가 두 줄로 쪼개짐 | 중간 | whitespace-nowrap 적용 |
| EC-20 | 어느 강의 페이지인지 맥락을 알 수 없음 | 중간 | 강의명·강사명 페이지 상단 표시 |

## 6. 데이터 모델 (v0.2 업데이트)

### `members` 컬렉션
```
{
  email: string,       // 소문자 정규화된 이메일
  name?: string,
  joinedAt: Timestamp
}
```

### `live_sessions/current` 문서
```
{
  isActive: boolean,
  maxCodes?: number,          // 최대 발급 수량 (미설정 시 무제한)
  scheduledAt?: Timestamp,    // [신규] 예정 시작 시각
  lectureTitle?: string,      // [신규] 강의명
  instructorName?: string,    // [신규] 강사명
  instructorContact?: string, // [신규] 강사/운영자 연락처
  startedAt?: Timestamp,
  endedAt?: Timestamp
}
```

### `issued_codes` 컬렉션
```
{
  // 문서 ID = 이메일 (소문자) — 중복 방지 핵심
  email: string,
  code: string,
  issuedAt: Timestamp,
  isUsed: boolean,
  usedAt?: Timestamp,
  isRevoked?: boolean         // [신규] 무효화 여부
}
```

### `issued_codes_meta/count` 문서 (신규)
```
{
  total: number  // 발급 총 건수 — 수량 한도 atomic 체크용
}
```

## 7. 용어 정의

| 용어 | 정의 |
|------|------|
| 라이브 세션 | 관리자가 활성화한 코드 발급 가능 구간 |
| 코드 | `LIVE-XXXXXXXX` 형식의 고유한 문자열 |
| 기존 가입자 | `members` 컬렉션에 이메일이 등록된 사용자 |
| 관리자 | 라이브 세션을 제어하고 발급 내역을 조회할 수 있는 내부 운영자 |
| 무효화 | 코드를 사용 불가 상태로 전환하는 행위 |
| 기발급 재확인 | 이미 발급된 코드를 다시 동일하게 반환하는 동작 |
