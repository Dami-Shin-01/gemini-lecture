## 1. 화면 목록

| ID | 화면명 | 경로 | 대상 |
|----|--------|------|------|
| SCR-01 | 코드 발급 폼 | `/` | 일반 사용자 |
| SCR-02 | 발급 완료 | `/` (인라인 전환) | 일반 사용자 |
| SCR-ERR-A | 이메일 형식 오류 | `/` (인라인) | 일반 사용자 |
| SCR-ERR-B | 라이브 시작 전 | `/` (인라인) | 일반 사용자 |
| SCR-ERR-C | 라이브 종료 후 | `/` (인라인) | 일반 사용자 |
| SCR-ERR-D | 미가입 이메일 | `/` (인라인) | 일반 사용자 |
| SCR-ERR-E | 수량 소진 | `/` (인라인) | 일반 사용자 |
| SCR-ERR-F | 네트워크·서버 오류 | `/` (인라인) | 일반 사용자 |
| SCR-03 | 관리자 로그인 | `/admin` | 관리자 |
| SCR-04 | 관리자 대시보드 — 세션 제어 | `/admin/dashboard` | 관리자 |
| SCR-05 | 관리자 대시보드 — 발급 내역 | `/admin/dashboard` (탭) | 관리자 |

> 모든 에러 화면은 별도 페이지 이동 없이 폼 영역 내에서 인라인으로 전환된다.

## 2. 사용자 플로우

```
[라이브 참여자]

       진입 (카카오톡 링크 등)
        │
        ▼
  ┌─────────────┐
  │   SCR-01    │  이메일 입력
  │  코드 발급 폼 │
  └──────┬──────┘
         │ 제출
         ▼
    ┌────────────────────────────────────────────────┐
    │                 클라이언트 검증                   │
    │         이메일 형식 오류? → SCR-ERR-A            │
    └────────────────────────────────────────────────┘
         │ 통과
         ▼
    ┌────────────────────────────────────────────────┐
    │               API 검증 (순서 중요)               │
    │  ① 기발급 이력 있음? → SCR-02 (코드 재노출)       │
    │  ② 라이브 비활성?                                │
    │     └ scheduledAt 미래 → SCR-ERR-B (시작 전)    │
    │     └ endedAt 과거   → SCR-ERR-C (종료 후)      │
    │  ③ 미가입 이메일?    → SCR-ERR-D                │
    │  ④ 수량 소진?        → SCR-ERR-E                │
    │  ⑤ 정상 발급         → SCR-02 (신규 코드)        │
    └────────────────────────────────────────────────┘
         │ 네트워크/서버 오류 발생
         └──────────────────────→ SCR-ERR-F


[관리자]

       진입 /admin
        │
        ▼
  ┌─────────────┐
  │   SCR-03    │  비밀번호 입력
  │ 관리자 로그인 │
  └──────┬──────┘
         │ 인증 성공
         ▼
  ┌─────────────────────────────┐
  │  SCR-04  관리자 대시보드      │
  │  ┌──────────┬─────────────┐ │
  │  │ 세션 제어 │  발급 내역   │ │  ← 탭 전환
  │  └──────────┴─────────────┘ │
  └─────────────────────────────┘
```

> **API 검증 순서 설계 원칙:** 기발급 이력 확인을 세션 활성 여부보다 먼저 수행한다.
> 세션이 종료된 후에도 코드를 잃어버린 학부모가 재확인할 수 있어야 하기 때문이다.

## 3. 화면 상세 — 사용자

---

### SCR-01. 코드 발급 폼

**경로:** `/`
**설명:** 사용자가 이메일을 입력하고 코드를 요청하는 메인 화면

```
┌─────────────────────────────────────────┐
│                                         │
│   [강의명] OO강사의 라이브 강의           │  ← 강사명·강의명 (회색 소형, 선택적)
│                                         │
│   코드 받기                              │  ← h1, 24px 이상, 굵게
│   강의에 등록하신 이메일을 입력하시면      │  ← 설명, 16px, 회색
│   코드를 바로 드립니다.                   │
│                                         │
│   이메일 주소                            │  ← 라벨, 14px
│   ┌─────────────────────────────────┐   │
│   │  예) 홍길동@naver.com            │   │  ← placeholder, 큰 input (48px 높이)
│   └─────────────────────────────────┘   │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │          코드 발급받기            │   │  ← 파란 버튼, 48px 높이
│   └─────────────────────────────────┘   │
│                                         │
└─────────────────────────────────────────┘
```

**UI 요소 상세**

| 요소 | 타입 | 속성 |
|------|------|------|
| 강의 컨텍스트 | `p` | 페이지 상단, 회색 소형. Firebase에서 강의 정보 fetch |
| 제목 | `h1` | "코드 받기", 24px 이상 |
| 설명 | `p` | 16px, 회색. "강의에 등록하신 이메일" — 익숙한 표현 사용 |
| 이메일 입력 | `input[type=email]` | 높이 48px, placeholder "예) 홍길동@naver.com", 포커스 시 파란 테두리, autocomplete="email" |
| 발급 버튼 | `button[type=submit]` | 높이 48px, 파란 배경, 로딩 중 비활성화 |

**상태별 화면 변화**

| 상태 | 변화 |
|------|------|
| 초기 | 폼 표시 |
| 로딩 | 버튼 내 스피너 + "확인하는 중이에요…", 버튼 비활성화 |
| 에러 | 에러 박스 인라인 삽입 (SCR-ERR-A~F 참조) |
| 성공 | SCR-02로 인라인 전환 |

### SCR-02. 발급 완료

**경로:** `/` (폼 영역을 결과 영역으로 교체)
**설명:** 코드 발급 성공 시 코드를 강조 노출하고 보존 방법을 안내

```
┌─────────────────────────────────────────┐
│                                         │
│   [강의명] OO강사의 라이브 강의           │
│                                         │
│   코드 받기                              │
│   강의에 등록하신 이메일을 입력하시면      │
│   코드를 바로 드립니다.                   │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │  ✓ 코드가 준비됐습니다!           │   │  ← 초록 배경, 굵게
│   │  (홍길동@naver.com)              │   │  ← 발급된 이메일 표시 (작은 글씨)
│   │                                 │   │
│   │   LIVE-4KQMR7BN                 │   │  ← 흰 배경, 검정, 28px 이상, mono
│   │                                 │   │     whitespace-nowrap 보장
│   │  ┌─────────────────────────┐    │   │
│   │  │   📋 코드 복사하기        │    │   │  ← 복사 버튼 (클릭 시 문구 변경)
│   │  └─────────────────────────┘    │   │
│   └─────────────────────────────────┘   │
│                                         │
│   지금 스크린샷을 찍어두시면 편리합니다.  │  ← 16px, 회색
│   화면을 닫으셔도 걱정 마세요.           │
│   같은 이메일을 다시 입력하면            │
│   코드를 다시 볼 수 있습니다.            │
│                                         │
│   강사 선생님께 이 화면을 그대로         │
│   보여주시면 됩니다.                     │
│                                         │
│   ── 다른 분의 코드를 받아드리려면? ──   │
│   다른 이메일로 받기                     │  ← 텍스트 링크 (소형)
│                                         │
└─────────────────────────────────────────┘
```

**상태 분기**

| 케이스 | 상단 메시지 | 색상 |
|--------|-----------|------|
| 신규 발급 | "✓ 코드가 준비됐습니다!" | 초록 |
| 기발급 재확인 | "이전에 발급받으신 코드입니다. 그대로 사용하시면 됩니다." | 파랑 |

**복사 버튼 동작**

| 상태 | 버튼 텍스트 |
|------|------------|
| 초기 | "📋 코드 복사하기" |
| 복사 성공 | "✓ 복사되었습니다!" (2초 후 원복) |
| 클립보드 미지원 | 버튼 숨기고 readonly input 노출 ("아래 코드를 꾹 눌러 복사하세요") |

## 4. 에러 화면 상세 — 사용자

> 모든 에러 화면은 폼 영역 내 인라인 박스로 표시된다.
> 폼(이메일 입력창·버튼)은 에러 박스 아래에 유지되어 재시도가 즉시 가능하다.
> 모든 에러 화면은 **① 무슨 상황인지 → ② 다음에 무엇을 하면 되는지** 순서로 안내한다.

---

### SCR-ERR-A. 이메일 형식 오류

**발생 조건:** 제출 시 이메일에 `@` 또는 `.` 미포함, 공백 포함 등

```
┌─────────────────────────────────────────┐
│                                         │
│   ┌─────────────────────────────────┐   │
│   │ ⚠️  이메일 주소를 확인해 주세요   │   │  ← 노란/주황 배경
│   │                                 │   │
│   │  @ 기호와 점(.)이 모두 있어야    │   │
│   │  합니다.                         │   │
│   │                                 │   │
│   │  올바른 예시:                    │   │
│   │  • 홍길동@naver.com             │   │
│   │  • kim1234@gmail.com           │   │
│   └─────────────────────────────────┘   │
│                                         │
│   이메일 주소                            │
│   ┌─────────────────────────────────┐   │  ← 입력창 테두리 빨간색으로 강조
│   │  (기존 잘못된 값 유지)            │   │
│   └─────────────────────────────────┘   │
│   ┌─────────────────────────────────┐   │
│   │          코드 발급받기            │   │
│   └─────────────────────────────────┘   │
│                                         │
└─────────────────────────────────────────┘
```

**설계 의도:** "형식 오류"라는 기술 용어 대신 구체적인 이유와 올바른 예시를 보여준다.

---

### SCR-ERR-B. 라이브 아직 시작 전

**발생 조건:** `live_sessions/current.isActive === false` && 아직 종료되지 않음 (startedAt 없거나 미래)

```
┌─────────────────────────────────────────┐
│                                         │
│   ┌─────────────────────────────────┐   │
│   │ 🕐 강의가 곧 시작됩니다          │   │  ← 파란 배경
│   │                                 │   │
│   │  아직 코드 발급이 시작되지        │   │
│   │  않았습니다.                     │   │
│   │                                 │   │
│   │  강사 선생님이 시작을 알려주시면  │   │  ← 다음 행동 지시
│   │  다시 이 페이지에서 받으실 수     │   │
│   │  있습니다.                       │   │
│   │                                 │   │
│   │  [scheduledAt이 있을 경우]       │   │
│   │  📅 예정 시작: 6월 5일 오후 3시  │   │  ← 조건부 표시
│   └─────────────────────────────────┘   │
│                                         │
│   이메일 주소                            │
│   ┌─────────────────────────────────┐   │
│   │  (이전 입력값 유지)               │   │
│   └─────────────────────────────────┘   │
│   ┌─────────────────────────────────┐   │
│   │       다시 시도해 보기            │   │  ← [다시 시도] 버튼
│   └─────────────────────────────────┘   │
│                                         │
└─────────────────────────────────────────┘
```

**설계 의도:** "오류"가 아닌 "대기 중" 상황으로 표현한다. 불안감 대신 안심감을 준다.

---

### SCR-ERR-C. 라이브 종료 후

**발생 조건:** `live_sessions/current.isActive === false` && `endedAt`이 과거

```
┌─────────────────────────────────────────┐
│                                         │
│   ┌─────────────────────────────────┐   │
│   │ 📌 코드 발급이 종료되었습니다    │   │  ← 회색 배경
│   │                                 │   │
│   │  오늘 강의의 코드 발급이          │   │
│   │  마감되었습니다.                  │   │
│   │                                 │   │
│   │  코드를 받지 못하셨다면           │   │  ← 다음 행동 지시
│   │  강사 선생님께 직접 문의해         │   │
│   │  주세요.                         │   │
│   │                                 │   │
│   │  📞 문의: 010-XXXX-XXXX         │   │  ← 클릭 시 전화 연결 (tel: 링크)
│   └─────────────────────────────────┘   │
│                                         │
│   혹시 이미 코드를 받으셨나요?           │  ← 안내 문구
│   이메일을 입력하면 받으신 코드를        │
│   다시 확인할 수 있습니다.               │
│                                         │
│   이메일 주소                            │
│   ┌─────────────────────────────────┐   │
│   │  (이전 입력값 유지)               │   │
│   └─────────────────────────────────┘   │
│   ┌─────────────────────────────────┐   │
│   │      발급된 코드 다시 확인하기    │   │  ← 버튼 텍스트 변경
│   └─────────────────────────────────┘   │
│                                         │
└─────────────────────────────────────────┘
```

**설계 의도:** 세션 종료 후에도 기발급 코드 재확인이 가능함을 명시적으로 안내한다.
API는 기발급 이력을 먼저 확인하므로, 이미 코드를 받은 사람은 SCR-02(코드 재노출)로 이동한다.

### SCR-ERR-D. 가입 정보 없음 (미가입 이메일)

**발생 조건:** 이메일이 `members` DB에 없음

```
┌─────────────────────────────────────────┐
│                                         │
│   ┌─────────────────────────────────┐   │
│   │ 🔍 이메일을 다시 확인해 주세요   │   │  ← 노란 배경
│   │                                 │   │
│   │  입력하신 이메일로 등록된         │   │
│   │  정보를 찾을 수 없습니다.         │   │
│   │                                 │   │
│   │  확인해 보세요:                  │   │  ← 체크리스트 형태
│   │  • 강의 신청할 때 쓴 이메일인가요? │
│   │  • @naver.com / @gmail.com 등   │   │
│   │    도메인까지 정확한가요?         │   │
│   │  • 혹시 다른 이메일 주소가 있나요? │
│   └─────────────────────────────────┘   │
│                                         │
│   이메일 주소                            │
│   ┌─────────────────────────────────┐   │
│   │  (이전 입력값 유지)               │   │
│   └─────────────────────────────────┘   │
│   ┌─────────────────────────────────┐   │
│   │          다시 시도하기            │   │
│   └─────────────────────────────────┘   │
│                                         │
│   ── [3회 이상 실패 시 추가 표시] ──     │
│                                         │
│   그래도 안 되신다면 강사 선생님께        │  ← 3회 실패 시 강조 노출
│   직접 문의해 주세요.                    │
│   📞 문의: 010-XXXX-XXXX              │  ← tel: 링크
│                                         │
└─────────────────────────────────────────┘
```

**설계 의도:**
- 1-2회 실패: 스스로 해결 가능한 힌트 제공
- 3회+ 실패: 운영자 연락처를 강조해 더 이상 혼자 해결하려 하지 않도록 유도

### SCR-ERR-E. 수량 소진

**발생 조건:** 발급 카운터가 maxCodes에 도달

```
┌─────────────────────────────────────────┐
│                                         │
│   ┌─────────────────────────────────┐   │
│   │ 😔 준비된 코드가 모두 소진됐습니다│   │  ← 주황 배경
│   │                                 │   │
│   │  오늘 강의의 코드가 모두          │   │
│   │  발급되었습니다.                  │   │
│   │                                 │   │
│   │  강사 선생님께 직접 말씀해         │   │  ← 다음 행동 지시

│   │                                 │   │
```

## 6. UX 설계 원칙 (40-50대 학부모 기준)

| 항목 | 기준 | 이유 |
|------|------|------|
| 본문 폰트 | 최소 16px | 노안 고려 |
| 코드 표시 폰트 | 28px 이상, 굵게, 모노스페이스 | 스크린샷 가독성 |
| 코드 줄바꿈 | `whitespace-nowrap` | 320px 구형폰에서 쪼개지지 않도록 |
| 버튼 높이 | 48px 이상 | 터치 타겟 (44px 최소 기준 + 여유) |
| 대비 | WCAG AA 이상 (4.5:1) | 야외·저조도 환경 가독성 |
| 에러 메시지 언어 | 일상어, 경어체 ("~해 주세요") | 기술 용어 사용 금지 |
| 이전 입력값 보존 | 에러 시 입력값 유지 | 다시 처음부터 입력하는 불편 방지 |
| 연락처 노출 | 모든 에러 화면에 포함 | 스스로 해결 못할 때 구제 수단 |
| 재시도 버튼 | 재시도 가능한 에러 화면 모두 포함 | 페이지 새로고침 없이 재시도 |
