## 2. 사용자 플로우

```
[라이브 참여 학부모]

       진입 (카카오톡 링크 등)
        │
        ▼
  ┌──────────────┐
  │   SCR-01A    │  이메일 입력
  │  이메일 입력  │
  └──────┬───────┘
         │ 제출
         ▼
    ┌─────────────────────────────────────────┐
    │          클라이언트 검증                  │
    │  이메일 형식 오류? → SCR-ERR-A           │
    └─────────────────────────────────────────┘
         │ 통과
         ▼
    ┌─────────────────────────────────────────┐
    │    POST /api/check-member              │
    │  미가입 이메일?  → SCR-ERR-D            │
    │  서버 오류?      → SCR-ERR-F            │
    └─────────────────────────────────────────┘
         │ 회원 확인 성공 (classId, className, scheduledAt 반환)
         ▼
  ┌──────────────┐
  │   SCR-01B    │  "고객님은 3반이세요."
  │  반 확인     │  [맞아요, 코드 받기] [아닌 것 같아요]
  └──────┬───────┘
         │
    ┌────┴────────────────────────┐
    │                             │
  [맞아요]                   [아닌 것 같아요]
    │                             │
    ▼                             ▼
  POST /api/issue-code        SCR-ERR-G
    │                         (운영자 문의 안내)
    ├─ 기발급 이력 있음 ──────→ SCR-02 (코드 재노출)
    ├─ 세션 비활성 (시작 전) → SCR-ERR-B
    ├─ 세션 비활성 (종료 후) → SCR-ERR-C
    ├─ 수량 소진 ────────────→ SCR-ERR-E
    ├─ 서버/네트워크 오류 ───→ SCR-ERR-F
    └─ 정상 발급 ────────────→ SCR-02 (신규 코드)


[관리자]

       진입 /admin
        │
        ▼
  ┌─────────────┐
  │   SCR-03    │  비밀번호 입력
  └──────┬──────┘
         │ 인증 성공
         ▼
  ┌─────────────────────────────┐
  │  SCR-04  관리자 대시보드     │
  │  ┌─────────────┬──────────┐ │
  │  │  반 제어    │ 발급 내역 │ │  ← 탭 전환
  │  └─────────────┴──────────┘ │
  └─────────────────────────────┘
```

> **API 검증 순서 설계 원칙:** `/api/issue-code`에서 기발급 이력 확인을 세션 활성 여부 확인보다 먼저 수행한다. 세션이 종료된 후에도 코드를 잃어버린 학부모가 재확인할 수 있어야 하기 때문이다.

## 3. 화면 상세 — 사용자

---

### SCR-01A. 이메일 입력 (1단계)

**설명:** 서비스 최초 진입 화면. 이메일만 입력.

```
┌─────────────────────────────────────────┐
│                                         │
│   코드 받기                              │  ← h1, 24px+, 굵게
│   강의에 등록하신 이메일을 입력하시면      │  ← 설명, 16px
│   어느 반인지 확인해 드릴게요.            │
│                                         │
│   이메일 주소                            │
│   ┌─────────────────────────────────┐   │
│   │  예) 홍길동@naver.com            │   │  ← 높이 48px
│   └─────────────────────────────────┘   │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │        내 반 확인하기             │   │  ← 파란 버튼, 높이 48px
│   └─────────────────────────────────┘   │
│                                         │
└─────────────────────────────────────────┘
```

**UI 요소 상세**

| 요소 | 속성 |
|------|------|
| 이메일 입력 | `type="email"`, 높이 48px, `autocomplete="email"`, placeholder "예) 홍길동@naver.com" |
| 확인 버튼 | 높이 48px, 파란 배경, 로딩 중 "확인하는 중이에요…" + 스피너 + disabled |

---

### SCR-01B. 반 확인 (1.5단계)

**설명:** 이메일 조회 성공 후 소속 반 정보를 보여주고 사용자가 맞는지 확인하는 단계.

```
┌─────────────────────────────────────────┐
│                                         │
│   코드 받기                              │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │  📋 고객님의 강의 정보           │   │  ← 파란 배경 박스
│   │                                 │   │
│   │  홍길동@naver.com               │   │  ← 입력한 이메일 (소형)
│   │                                 │   │
│   │  3반                            │   │  ← 반 이름, 28px+, 굵게
│   │  6월 10일 (화) 오후 2:00        │   │  ← 강의 예정 시각, 16px
│   │                                 │   │
│   └─────────────────────────────────┘   │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │   ✓  맞아요, 코드 받기           │   │  ← 초록 버튼, 높이 52px, 굵게
│   └─────────────────────────────────┘   │
│                                         │
│   이 반이 아닌 것 같아요                  │  ← 텍스트 링크 (소형, 회색)
│                                         │
└─────────────────────────────────────────┘
```

**UI 요소 상세**

| 요소 | 속성 |
|------|------|
| 반 이름 | 28px 이상, 굵게, 검정. 예: "3반" |
| 강의 예정 시각 | 16px, 회색. scheduledAt이 없으면 미표시 |
| 확인 버튼 | 초록 배경, 높이 52px (강조). 세션 활성 시 "맞아요, 코드 받기" / 비활성 시 "강의 시작 후 코드 받기" |
| 아닌 것 같아요 | 텍스트 링크, 클릭 시 SCR-ERR-G. 버튼과 **최소 24px 간격** 확보 (EC-N04 대응) |

**상태 분기**

| 상황 | 처리 |
|------|------|
| 반 세션 현재 활성 (isActive=true) | 일반 표시. 버튼 "맞아요, 코드 받기" |
| 반 세션 비활성 (시작 전) | 박스 하단에 "아직 **3반** 강의가 시작되지 않았어요." 안내 추가. 버튼 텍스트 "강의 시작 후 코드 받기"로 변경 (EC-N07 대응) |

> **EC-N04 대응:** "이 반이 아닌 것 같아요" 링크를 버튼과 시각적으로 확실히 구분 (크기·색·간격). 오클릭 시 SCR-ERR-G에서 "돌아가서 코드 받기" 버튼으로 복귀 가능.
>
> **EC-N06 대응:** 이 화면 진입 시 `sessionStorage`에 이메일 저장. 새로고침/앱 전환 후 재진입해도 SCR-01A에 이메일 자동 복원.

### SCR-02. 발급 완료

**설명:** 코드 발급 성공 (신규 또는 기발급 재확인)

```
┌─────────────────────────────────────────┐
│                                         │
│   코드 받기                              │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │  ✓ 코드가 준비됐습니다!           │   │  ← 초록 배경
│   │  홍길동@naver.com · 3반          │   │  ← 이메일·반 이름 (소형, 회색)
│   │                                 │   │
│   │  ┌───────────────────────────┐  │   │
│   │  │   LIVE-4KQMR7BN          │  │   │  ← 흰 배경, 검정, 28px+
│   │  └───────────────────────────┘  │   │     whitespace-nowrap
│   │                                 │   │
│   │  ┌─────────────────────────┐    │   │
│   │  │   📋 코드 복사하기        │    │   │  ← 복사 버튼
│   │  └─────────────────────────┘    │   │
│   └─────────────────────────────────┘   │
│                                         │
│   지금 스크린샷을 찍어두시면 편리합니다.  │
│   화면을 닫으셔도 걱정 마세요.           │
│   같은 이메일을 다시 입력하면            │
│   코드를 다시 볼 수 있습니다.            │
│                                         │
│   강사 선생님께 이 화면을 그대로         │
│   보여주시면 됩니다.                     │
│                                         │
│   다른 이메일로 받기                     │  ← 텍스트 링크 (소형)
│                                         │
└─────────────────────────────────────────┘
```

**상태 분기**

| 케이스 | 상단 메시지 |
|--------|-----------|
| 신규 발급 | "✓ 코드가 준비됐습니다!" (초록) |
| 기발급 재확인 | "이전에 발급받으신 코드입니다. 그대로 사용하시면 됩니다." (파랑) |

**복사 버튼 동작**

| 상태 | 텍스트 |
|------|--------|
| 초기 | "📋 코드 복사하기" |
| 복사 성공 | "✓ 복사되었습니다!" (2초 후 원복) |
| 클립보드 미지원 | 버튼 숨기고 readonly input 노출 ("아래 코드를 꾹 눌러 복사하세요") |

## 4. 에러 화면 상세 — 사용자

> 공통 원칙: 모든 에러 화면은 **① 상황 설명 → ② 해결 방법 → ③ 운영자 연락처** 순서로 구성한다.

---

### SCR-ERR-A. 이메일 형식 오류

**발생:** 제출 시 이메일에 @ 또는 . 미포함, 공백 포함 등

```
┌─────────────────────────────────────────┐
│   ┌─────────────────────────────────┐   │
│   │ ⚠️  이메일 주소를 확인해 주세요   │   │  ← 노란 배경
│   │                                 │   │
│   │  @ 기호와 점(.)이 모두 있어야    │   │
│   │  합니다.                         │   │
│   │                                 │   │
│   │  올바른 예시:                    │   │
│   │  • 홍길동@naver.com             │   │
│   │  • kim1234@gmail.com           │   │
│   └─────────────────────────────────┘   │
│                                         │
│   이메일 주소  [이전 값 유지, 테두리 빨강] │
│   [내 반 확인하기]                       │
└─────────────────────────────────────────┘
```

### SCR-ERR-F. 인터넷·서버 오류

**발생:** fetch 실패, 타임아웃, 서버 500

```
┌─────────────────────────────────────────┐
│   ┌─────────────────────────────────┐   │
│   │ 📶 연결이 원활하지 않습니다      │   │  ← 빨간/주황 배경
│   │                                 │   │
│   │  해결 방법:                      │   │
│   │  1. 와이파이나 데이터가 연결되어  │   │

### SCR-ERR-G. 반 불일치 신고

**발생:** SCR-01B에서 "이 반이 아닌 것 같아요" 선택 시

```
┌─────────────────────────────────────────┐
│   ┌─────────────────────────────────┐   │
│   │ 🙋 강사 선생님께 확인해 주세요   │   │  ← 보라/인디고 배경
│   │                                 │   │
│   │  입력하신 이메일에               │   │
│   │  홍길동@naver.com               │   │  ← 이메일 명시 (EC-N03 대응)
│   │  → 3반 으로 등록되어 있습니다.   │   │  ← 조회된 반 이름 명시
│   │                                 │   │
│   │  다른 반에 수강 신청하셨다면      │   │
│   │  강사 선생님께 말씀해 주시면      │   │
│   │  수정해 드릴 수 있습니다.         │   │
│   │                                 │   │
│   │  📞 010-XXXX-XXXX              │   │
│   └─────────────────────────────────┘   │
│                                         │
│   ┌─────────────────────────────────┐   │
│   │   ← 돌아가서 코드 받기           │   │  ← (EC-N04 대응) SCR-01B 복귀 버튼
│   └─────────────────────────────────┘   │
│                                         │
│   다른 이메일로 다시 시도하기            │  ← 텍스트 링크 → SCR-01A
│                                         │
└─────────────────────────────────────────┘
```

> **EC-N04 대응:** "이 반이 아닌 것 같아요"를 오클릭했을 때 패닉 없이 복귀 가능. "돌아가서 코드 받기" 버튼이 있어 SCR-01B로 즉시 돌아갈 수 있음.
> **EC-N03 대응:** 이메일과 조회된 반을 함께 표시해 운영자와 전화 통화 시 빠른 확인 가능.

### SCR-ERR-H. 반 배정 오류 (시스템 오류)

**발생:** `members.classId` 미설정 또는 해당 `classes` 문서가 없는 경우 (EC-N01, EC-N02 대응)

```
┌─────────────────────────────────────────┐
│   ┌─────────────────────────────────┐   │
│   │ ⚠️  반 배정 정보를 확인 중입니다  │   │  ← 주황 배경

│   │                                 │   │
│   │  강사 선생님께 아래 내용을        │   │
│   │  알려주시면 빠르게 도와드릴게요.   │   │
│   │                                 │   │
│   │  • 입력하신 이메일               │   │

## 6. UX 설계 원칙 (40-50대 학부모 기준)

| 항목 | 기준 | 이유 |
|------|------|------|
| 본문 폰트 | 최소 16px | 노안 고려 |
| 반 이름 표시 | 28px 이상, 굵게 | 핵심 정보라 강조 |
| 코드 표시 | 28px 이상, 굵게, 모노스페이스, 흰 배경 | 스크린샷 가독성 |
| 코드 줄바꿈 | `whitespace-nowrap` | 320px 구형폰 대응 |
| 버튼 높이 | 48px 이상, 확인 버튼 52px | 터치 타겟 |
| 대비 | WCAG AA (4.5:1 이상) | 야외·저조도 가독성 |
| 에러 언어 | 일상어, 경어체 | "서버 오류" 등 기술 용어 금지 |
| 이전 입력값 보존 | 에러 시 이메일 입력값 유지 | 재입력 불편 방지 |
| 운영자 연락처 | 모든 에러 화면에 포함 | 최후 구제 수단 |
| 재시도 버튼 | 재시도 가능한 에러 화면에 포함 | 새로고침 없이 재시도 |
